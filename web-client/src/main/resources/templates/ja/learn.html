ID Token → クライアント

OIDC 認証の結果を表します。aud は web-client で、API 用の認証情報としては使用できません。



Access Token → API
aud に resource-api が含まれ、scope が許可された操作を表します。JWT は符号化・署名されますが、暗号化されているとは限りません。


Refresh Token → サーバー
サーバーのメモリーにのみ保存し、新しい Access Token の取得に使用します。ブラウザーの localStorage には保存しません。アプリを再起動した場合は再ログインが必要です。


API の認可を試す
Web サーバーが Access Token のみを付けてリクエストします。Alice が注文2を読むと403、Admin は全注文を読めます。ユーザートークンでマシン専用エンドポイントを呼ぶと403になります。







プロトコルを観察する
認可リクエスト：response_type=code、state、code_challenge、code_challenge_method=S256。
トークン交換：サーバーからの POST フォームに code と code_verifier を含めます。実際の値をログやスクリーンショットに残さないでください。
401は認証情報の欠如・無効、403は認証後の権限不足を表します。主体の識別には iss + sub を使用します。




ログアウトしても発行済み JWT は直ちに無効にはなりません。この実験の Access Token の有効期間は120秒です。
